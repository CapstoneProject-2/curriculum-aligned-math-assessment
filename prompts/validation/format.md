버전: v2, v3 공통
사용 시기: 2차·3차 실험 (생성 후 재검증 단계 — consistency.md의 정합성 검증과 별도로 항상 실행)
모델: 해당없음 — LLM을 호출하지 않는 규칙 기반(rule-based) 코드 검증
직전 버전 대비 변경: 해당없음
변경 이유: LLM 정합성 검증이 API 오류·JSON 파싱 실패 등으로 동작하지 못할 때도 최소한의 품질 기준(필수 요소 존재, 길이, 명령형 어미)은 항상 확인하기 위함

## 안내

이 파일은 LLM 프롬프트가 아니라, `src/generation/v3_final.py`의 `basic_validation_fallback()` 함수에 구현된 **규칙 기반 판정 로직**을 문서화한 것이다. 지도교수 확인 요청(저장소 정리 가이드 9번 항목 "2. `basic_validation_fallback` 함수 본문 — 2차 형식 검증의 실제 판정 기준")에 대응하는 문서.

## 판정 기준 (코드 순서대로)

1. **필수 요소 존재**: `question`(문제), `answer`(정답), `explanation`(해설) 중 하나라도 비어 있으면 즉시 실패 처리.
2. **문제 길이**: 문제 텍스트 길이가 20자 미만이거나 500자를 초과하면 실패 처리.
3. **명령형 종결어미 포함 여부**: 아래 키워드 중 하나라도 문제 텍스트에 포함되어 있는지 확인.
   ```
   구하시오, 계산하시오, 설명하시오, 나타내시오, 작성하시오, 구하여라, 오, 라, 요, 하세요, 하라, 하시오
   ```
   단, 이 조건은 **없어도 검증 실패로 처리하지 않는다** — 코드 주석상 "명령형 지시문이 없지만 문제 내용으로 판단하여 통과"로 로그만 남기고 넘어간다.
4. **최종 판정**: 위 1·2번을 통과하면(요소 존재 + 길이 20~500자) `is_valid: true`로 반환한다.

## 반환값 형태

```json
{"is_valid": true, "error": "", "confidence": "보통"}
```
또는 실패 시:
```json
{"is_valid": false, "error": "문제, 정답, 해설 중 누락된 요소가 있습니다.", "confidence": "높음"}
```
```json
{"is_valid": false, "error": "문제 길이가 적절하지 않습니다.", "confidence": "보통"}
```

## 비고

- 대응 코드: `src/generation/v3_final.py`의 `basic_validation_fallback()` 함수.
- 이 형식성 검증은 정합성 검증(`consistency.md`)과 **매 시도마다 항상 함께 실행**되며(코드 주석: "1단계 통과 여부와 관계없이 항상 실행"), 둘 다 통과해야 최종 채택된다 (v3 AND 조건, v2 비고 참고).
- 3번 항목(명령형 종결어미)의 키워드 목록에 "오", "라", "요" 같은 한 글자 어미가 포함되어 있어, 사실상 대부분의 한국어 서술형 문장에서 조건을 만족하게 된다. 이 조건이 실질적으로 판정에 거의 영향을 주지 않는다는 점은 논문 Limitation이나 재현 시 참고할 만하다.
